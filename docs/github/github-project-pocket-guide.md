# Guia de Bolso do GitHub Project

## Para que serve

Este guia resume o uso diario do board. Ele complementa o [guia completo](./github-project-guide.md) sem substituir os detalhes de processo.

## Regras rapidas

- `Epic` e para capacidades grandes.
- `Story` e para entregas pequenas com valor claro.
- `Tech Task` e para trabalho tecnico derivado.
- `Spike` e para investigacao e decisao.
- `Bug` e para defeitos.

## Labels que usamos

- `type: epic`, `type: story`, `type: tech-task`, `type: spike`, `type: bug`
- `area: architecture`, `area: frontend`, `area: content`, `area: platform`, `area: analytics`, `area: security`, `area: accessibility`, `area: product`
- `priority: p0`, `priority: p1`, `priority: p2`, `priority: p3`
- `blocked`, `needs-refinement`, `ready-for-dev`, `ready-for-review`

## Colunas do board

- `Backlog`: ainda em definicao ou aguardando prioridade
- `Ready`: pronto para iniciar
- `In Progress`: em execucao
- `In Review`: aguardando revisao ou validacao final
- `Blocked`: impedido por dependencia
- `Done`: concluido

## Checklist minimo antes de publicar

- o tipo esta correto
- a area esta correta
- a prioridade esta definida
- o texto nao expõe segredo ou detalhe sensivel
- o criterio de aceite deixa claro quando terminar
- o item foi colocado na coluna correta

## Regra pratica

Se houver duvida sobre escopo, manter o item em refinamento e registrar a decisao no backlog antes de executar.
